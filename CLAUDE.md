## 2. Границы ролей

- Код (`backend/`, `frontend/`) правлю напрямую Edit/Write.
  `docs/`, `documentation/`, обвязку — тоже.
- **Тесты, коммиты, теги, деплой, миграции — всегда Ксения.** Я выдаю
  команды, не выполняю их.
- Коммит-сообщения — только на английском. Общение — по-русски.
- Нужен выбор — задать вопрос явно, а не проговорить варианты в тексте.

## 3. Git из песочницы

⛔ **Только `git log`, `git show`, `git describe`.**
`git status` и `git branch` НЕ только читают: они обновляют индекс и берут
`.git/index.lock`, после чего `git add` на Windows падает.
Безопасный вид статуса: `git --no-optional-locks status`.
Убирать залипший лок — Ксения (из песочницы не видно, не держит ли его
VS Code): сначала `Get-Process git`, и только если пусто — удалять.

## 4. Про проверки

**Проверка ловит только то, что подозреваешь.** 12.08 всё, что
проверялось машиной, поймалось (`model_json_schema()`, прогон фильтра
по 50 материалам, `docs_audit.py`); сбежало то, что считалось общим
знанием, а не проектным. Поэтому подозревать надо в первую очередь
привычное: git, импорты, стиль тестов, процедуру выкладки.

Скрипты, которые дёшево прогнать:
- `cd backend && python scripts/morning_check.py` — начало дня;
- `cd backend && python scripts/docs_audit.py` — перед выкладкой
  и раз в несколько дней.

## 5. Ловушки окружения

- `prompt_config.py` — в `.gitignore`, но НЕ в `.dockerignore`: правки
  промптов уезжают на прод образом при `fly deploy`, а не коммитом.
- Правя эндпоинты — `python scripts/dump_openapi.py`, иначе CI красный.
- `flyctl` запускать из КОРНЯ репозитория (в `backend/` нет `fly.toml`).
- Прод-база не подменяется никогда. Направление переноса только
  прод → дев.
- Цифры заполнения данных смотреть ТОЛЬКО на проде; в замере называть
  контур и дату, иначе это не факт, а воспоминание.
- Сетевой прокси песочницы режет JSON-API — «не достучались» отсюда
  не значит «недоступно у Ксении».
- Windows-бинарники в `node_modules` в песочнице не запускаются:
  фронтенд-тесты и линт гоняет только Ксения.
